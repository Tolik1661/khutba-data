# Робот: автозагрузка хутб и лекций

Раз в 6 часов (в 03:17, 09:17, 15:17 и 21:17 по Москве) GitHub запускает `robot/robot.py`. Робот смотрит
источники, находит новые посты со звуком и добавляет их в приложение.

## Что происходит с каждым постом

1. **Отбор.** Берутся только посты с аудиофайлом или голосовым сообщением. Записи короче
   45 секунд пропускаются.
2. **Разбор описания.** Подпись поста, название файла и дата уходят в модель Claude. Она
   возвращает тип (хутба / лекция / пропустить), название, лектора, дату и уверенность.
3. **Проверка на повтор.** Если запись с таким названием у этого лектора уже есть, пост
   пропускается. Для коротких названий вроде «Хьэдис дерс» повтором считается только запись
   с датой в пределах недели.
4. **Звук.** Файл скачивается и сжимается в mp3 (моно, 48 кбит/с — около 0,36 МБ на минуту),
   затем кладётся в `audio/`. Длительность записывается в поле `duration`.
5. **Куда попадает запись.**
   - источник с `"auto_publish": true` и уверенность `high` → сразу в `khutba.json`,
     то есть в приложение;
   - всё остальное → в `drafts.json`. Черновики видны в админке на вкладке «Черновики»:
     там запись можно прослушать, поправить и опубликовать или удалить.
6. **Память.** В `robot/state.json` записано, какие посты уже обработаны, поэтому повторный
   запуск ничего не дублирует.

Робот только добавляет записи. Существующие записи в `khutba.json` он не меняет и не удаляет —
это проверяется перед каждой записью файла.

## Как оформляется описание

Авторам ничего менять не нужно: робот сам приводит подпись к единому виду.

| Поле | Правило |
|---|---|
| Раздел | «Хутбы», если в тексте есть «хутба», «хъутIбэ», «пятничная проповедь»; иначе «Лекции» |
| Название | Только тема, на языке оригинала, без перевода. Убираются эмодзи, хештеги, дата в начале, слова «Хутба (на русском):», «Вопрос № 278:», имя лектора в конце и внешние кавычки |
| Лектор | Имя из `sources.json` для этого источника. Другое имя ставится, только если оно прямо указано в посте, и такая запись всегда уходит в черновики |
| Дата | Дата из текста поста; если её нет — дата исходной публикации (для пересланных) или дата поста. Для хутбы без даты — ближайшая прошедшая пятница |
| Пропуск | Объявления, книги и PDF, реклама, сборы, Коран без толкования, нашиды, а также запись, где одна хутба повторена сразу на двух языках |

Пример: пост «🎙 Вопрос № 278: «Семь пунктов, которые необходимо знать…» — Абу Ислам
аш-Шаркаси» превращается в лекцию с названием «Семь пунктов, которые необходимо знать…».

Полный текст правил — в переменной `PROMPT` в `robot.py`. Чтобы изменить правило, поправьте
его там обычными словами.

## Telegram-бот (`tgbot.py`)

Каждый новый черновик робот присылает в бота карточкой: звук, название, лектор, дата,
ссылка на исходный пост. Под карточкой три кнопки:

- **✅ Опубликовать** — запись переходит в `khutba.json`, то есть в приложение;
- **✏️ Изменить** — название, лектор, дата или перенос между «Хутбами» и «Лекциями».
  Бот просит прислать новое значение ответом на своё сообщение и обновляет карточку;
- **🗑 Удалить** — после подтверждения черновик и его аудиофайл удаляются.

Внизу экрана — постоянное меню с кнопками: «Черновики», «Опубликованные» (с кнопкой «Снять с
публикации»), «Источники» (включить или выключить источник и автопубликацию), «Состояние»
(когда работал робот и сколько занято места), «Проверить сейчас», «Справка». Под ответами
бота есть кнопки следующего шага. Те же действия доступны командами `/drafts`, `/recent`,
`/sources`, `/status`, `/run`, `/help`.

Оповещения приходят сами: источник недоступен, пост не обработался за три попытки,
место под аудио занято на 80 %, новой хутбы нет больше недели, не настроен вход в Telegram.

Бот слушается только чатов из `TG_ADMIN_CHAT_IDS`. Любому другому он отвечает одним
сообщением с его chat id — так владелец узнаёт свой id при настройке.

Бот запускается раз в 5 минут. Первое нажатие обрабатывается при ближайшем запуске
(обычно в пределах 5–10 минут), после него бот остаётся на связи ещё 3 минуты
и отвечает сразу.

## Источники (`sources.json`)

```json
{
  "id": "abu_islam",
  "title": "Telegram: Абу Ислам аш-Шаркаси",
  "type": "telegram",
  "channel": "abu_islam_official",
  "speaker": "Абу Ислам аш-Шаркаси",
  "default_kind": "lecture",
  "auto_publish": false,
  "backfill": 30,
  "enabled": true
}
```

- `type` — `telegram` (нужен `channel`) или `youtube` (нужен `channel_id`).
- `speaker` — имя лектора, как оно будет показано в приложении.
- `default_kind` — раздел для постов, по тексту которых тип не понять.
- `auto_publish` — `true`: уверенные записи публикуются сразу; `false`: всё идёт в черновики.
- `backfill` — сколько последних постов просмотреть при первом запуске.
- `enabled` — `false` выключает источник.

Чтобы добавить лектора, скопируйте блок, поменяйте `id`, `channel` и `speaker`.

## Секреты репозитория

Settings → Secrets and variables → Actions:

| Имя | Что это |
|---|---|
| `ANTHROPIC_API_KEY` | Ключ API с platform.claude.com — для разбора описаний |
| `TG_API_ID`, `TG_API_HASH` | Выдаются на my.telegram.org → API development tools |
| `TG_SESSION` | Строка входа в Telegram, её печатает `python robot/tg_login.py` |
| `TG_BOT_TOKEN` | Токен бота от @BotFather |
| `TG_ADMIN_CHAT_IDS` | Chat id админов через запятую. Свой id бот сообщает в ответ на /start |

Вход в Telegram нужен потому, что открытая веб-версия каналов не отдаёт аудиофайлы.
`TG_SESSION` даёт полный доступ к аккаунту, поэтому лучше завести для робота отдельный
аккаунт. Отозвать доступ: Telegram → Настройки → Устройства.

## Запуск вручную

```bash
pip install -r robot/requirements.txt
python robot/robot.py --dry-run            # показать решения, ничего не записывая
python robot/robot.py --source abu_islam   # один источник
```

Нужен установленный `ffmpeg`.

## Ограничения

- Аудио лежит в самом репозитории, а у GitHub Pages лимит 1 ГБ. Сорокаминутный урок — около
  15 МБ, хутба — 2–3 МБ. Когда место подойдёт к концу, хранение нужно будет перенести.
- С YouTube звук скачивается через `yt-dlp`. С серверов GitHub YouTube такие запросы часто
  блокирует, поэтому YouTube-источник выключен и оставлен как запасной.
